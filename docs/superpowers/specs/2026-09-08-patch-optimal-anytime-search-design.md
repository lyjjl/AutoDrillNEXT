# 矿区范围任意时刻最优搜索

> 本规格纠正 `2026-09-07-bounded-optimal-mining-planner.md` 的证明契约；两者冲突时以本规格为准。

## 决策

“局部最优”不再表示一次删除、交换或邻域搜索已经无法继续改进。产品统一使用以下术语：

- **当前最佳**：在时间或状态预算内，当前已找到并通过完整验证的最佳方案；不承诺不存在更优方案。
- **针对该矿区最优**：在本次固定规划快照和支持模型内，所有可能优于当前方案的状态均已展开或被安全证明不可能更优。
- **已证明无解**：同一有限搜索域已经耗尽，且不存在通过完整验证的方案。

该改造采用任意时刻算法：先快速给出当前最佳，再在剩余预算内尝试完成证明。只有证明搜索队列耗尽时，UI 才能显示“针对该矿区最优”。

## 当前实现差距

`docs/superpowers/specs/2026-09-07-bounded-optimal-mining-planner.md` 的目标是受限域最优，但当前实现尚未满足该契约：

- `OptimalMiningPlanner` 枚举钻头子集，但用启发式 `ItemRouteSolver` 回调评价布局；布局枚举完成不能证明运输拓扑最优。
- `TransportPathEnumerator` 只枚举最短地面路径，不覆盖桥、端口、混合运输、容量共享或非最短但更低材料成本的路径。
- `LocalMiningPlanner` 在最终结果中固定构造 `optimal=false`，并始终继承 `SEARCH_LIMIT_REACHED`。
- `ObjectiveValue.compareTo` 是吞吐优先，而生产选择还对 `LOW_COST` 和 `LOW_COMPLEXITY` 使用额外排序；现有上下界无法在所有配置下表达同一个目标顺序。
- `SupportPlanner`、预算选择和动态模拟仍位于布局搜索回调内部；除非它们的有限选择域也被枚举或证明支配，否则不能参与矿区最优证明。

因此本规格替代旧规格中“现有联合求解器已能给出最优证书”的实现假设，但保留其有限快照、无外部求解器和确定性要求。

## 证明范围

一次证书绑定不可变的 `PatchSearchScope`：

- `WorldSnapshot` 及其 `TerrainRevision`；
- `OrePatch` 的矿种和绝对矿格集合；
- 本次捕获的有限地图瓦片集合；运输路线可使用集合内的非矿区瓦片；
- `CapabilitySnapshot` 中当前可用且模型支持的钻头、运输和配套设施；
- `Inventory`、预算模式、队伍、现有网络占用；
- 已解析的出口锚点；
- `PlannerRequest` 的配置、目标产出、运输余量、混合运输开关和状态上限；
- 用户选择的钻头和液体选项。

证书只声明“在该快照和当前支持模型内最优”，不声明现实世界永久最优。世界修订、库存、科技、队伍、出口、设置或用户选择任一变化都会使证书失效，并继续沿用现有提交前重验。

无法建立完整有限域的内容不得静默忽略。若某个必需方块的端口、占地、产量、容量或支持语义不受模型支持，该搜索可以返回当前最佳，但不能返回“针对该矿区最优”。

## 目标顺序

证书必须使用与用户当前配置完全相同的排序，而不是固定调用 `ObjectiveValue.compareTo`：

- `BALANCED`、`THROUGHPUT`：可持续出口产出、独立矿格覆盖、材料、空间、复杂度、规范 ID。
- `LOW_COST`：总计划成本优先，然后使用现有产出、覆盖和稳定规范顺序。
- `LOW_COMPLEXITY`：复杂度优先、总计划成本其次，然后使用现有产出、覆盖和稳定规范顺序。

新增单一 `PlanObjectiveOrder`，同时负责完整方案比较、部分状态乐观上界比较和证书上下界校验。生产选择、搜索队列和最终主方案选择必须调用它；UI 只呈现结果，不自行排序。Pareto frontier 继续展示非支配备选，但不决定主方案。

浮点产出继续使用 `ObjectiveValue.outputRank` 的 0.0001 件/秒桶。规范 ID 只用于确定性平局，不代表用户价值。

## 架构

### 快速下界阶段

保留现有 `MiningLayoutSolver` 和 `ItemRouteSolver` 作为热启动器。它们负责尽快找到第一个完整可行方案，并可继续产生更好的 incumbent。其结果必须经过支持、预算、物理验证和动态模拟后才能成为证书下界。

启发式剪枝、候选数量上限和局部精简均不能关闭证明分支。它们只影响多快找到下界，不影响“针对该矿区最优”的判断。

快速阶段和证明阶段共享现有两秒绝对截止时间。证明队列先创建根状态；热启动最多使用总搜索预算的 25%，并接收独立的协作截止时间，剩余至少 75% 留给证明搜索。找到首个可行方案后立即转入证明阶段。热启动内部每个布局和路由扩张都检查该截止时间，不得以一次未受控的启发式调用耗尽证明预算。

### 证明搜索协调器

新增 `PatchOptimalSearch`，持有按乐观目标排序的优先队列。搜索状态只包含不可变、可规范化的数据：

- 钻头候选的 include/exclude 游标；
- 已选钻头、占用瓦片和已覆盖矿格；
- 已决定、未决定的运输放置配置；
- 尚未满足的钻头供给和配套需求；
- 当前固定成本、可行流下界和目标乐观上界；
- 规范状态 ID。

每次弹出一个非支配状态才增加 `exploredStates`。达到绝对截止时间、`maxIterations` 或线程取消时立即停止；队列保留的最大乐观值成为证书上界。

队列为空时才算搜索域耗尽。存在有效 incumbent 时返回 `PATCH_OPTIMAL`；没有 incumbent 时返回 `PROVEN_INFEASIBLE`。

### 完整钻头域

`CandidateGenerator` 必须在有限快照内生成所有满足当前选择和地形规则的钻头放置，不得使用 `maxIterations` 截断候选生成。候选按内容 ID、锚点、朝向和规范 ID 排序。

布局状态按该顺序分支“跳过”或“采用”。占地重叠、候选冲突和必然无法超过 incumbent 的状态使用安全上界剪枝。矿格覆盖按绝对瓦片去重。

### 精确运输子问题

对每个仍可能击败 incumbent 的布局，构建有限 `TransportPlacementDomain`：

- 每个可放置瓦片上的内容 ID、朝向、输出方向；
- 每个合法桥发送端/接收端对及配置；
- 每个钻头到所有合法相邻接收端的源边；
- 所有与选定出口匹配的终端配置；
- 同一瓦片或足迹上的互斥放置组；
- 端口接收、自动桥连接干扰、桥范围、容量和运输余量。

证明搜索对“启用哪个放置配置”进行分支定界。未决定配置在流量松弛中按免费、可用处理，以计算不会低估真实可能产出的乐观上界；固定配置通过现有 `FlowSolver` 检查单一货物流量。共享传送带和桥容量属于同一个流网络，不能按钻头独立求路后相加。

达到目标吞吐和覆盖后，继续以活动配置成本、占地和复杂度分支，直到不存在相同主目标但更便宜的网络。桥端点作为原子约束；每个瓦片最多一个配置；所有完整网络必须无环并最终到达出口。

`TransportPathEnumerator` 不再承担证明职责。若其最短地面路径能力仍只服务测试或热启动，则保留并明确命名；否则删除，避免把不完整枚举器误作证书域。

### 配套设施、预算与模拟

一个完整运输状态还必须覆盖所有有限支持选项：

- `SupportPlanner` 提供规范排序的可行支持变体，而不是只返回第一个启发式选择；
- 预算在总钻头、运输和支持成本上验证；
- `ItemSimulationEvaluator` 只会降低静态流下界，因此静态最大流可作为产出的安全乐观上界；
- 若能力明确声明使用现有静态或有界模型，证书范围记录该保真度，并可证明模型内最优；
- 若所选方案依赖 `UNSUPPORTED` 或无法界定的模拟、支持语义，仍可返回当前最佳，但不能完成证明。

## 安全剪枝

允许进入证明路径的剪枝必须附带可测试的不变量：

- 钻头足迹、运输足迹或现有占用冲突；
- 当前状态在放宽端口和成本后仍无法连接出口；
- 剩余钻头生产总和与放宽运输最大流共同给出的产出上界不优于 incumbent；
- 剩余候选矿格并集给出的覆盖上界不优于 incumbent；
- 在主目标已相等时，当前固定成本或复杂度下界已劣于 incumbent；
- 相同规范状态键下，一个标签在产出能力、覆盖可能性、固定成本、占地和复杂度上被另一个标签弱支配。

固定搜索半径、只保留第一条路径、只保留最短路径、任意候选数量上限、随机取样和未证明的“看起来更近”规则只能用于热启动，不能用于证书搜索。

## 结果与证书

将布尔语义扩展为显式状态：

```java
enum SearchVerdict {
    NONE,
    SEARCH_INCOMPLETE,
    CURRENT_BEST,
    PATCH_OPTIMAL,
    PROVEN_INFEASIBLE
}
```

`OptimalityCertificate` 至少包含：

- `SearchVerdict verdict`；
- `PatchSearchScope scope` 或其稳定摘要；
- 当前配置的目标顺序；
- `exploredStates`、`prunedStates`、`pendingStates`；
- 已验证 incumbent 目标；
- 未决状态的最大乐观目标；
- 阻止证明完成的原因：时间、状态上限、不完整模型或无；
- 诊断列表。

兼容读取可保留 `optimal()` 计算属性，其值只在 `verdict == PATCH_OPTIMAL` 时为真。不得继续由调用方手工构造永远为假的最终证书。

不变量：

- `SEARCH_INCOMPLETE`：未决状态仍存在但尚无有效 incumbent，携带搜索上限或模型不完整诊断；不得描述为无解；
- `CURRENT_BEST`：incumbent 存在，未决上界不低于 incumbent，并携带 `SEARCH_LIMIT_REACHED` 或模型不完整诊断；
- `PATCH_OPTIMAL`：incumbent 存在，队列为空，上下界在当前目标顺序下相等，不携带 `SEARCH_LIMIT_REACHED`；
- `PROVEN_INFEASIBLE`：队列为空且无 incumbent；
- `NONE`：尚未形成可比较的规划域，例如矿区或出口解析失败。

## UI 与过程显示

规划面板继续实时显示实际搜索，不播放伪造轨迹。状态文案改为：

- `当前最佳 · 搜索仍在进行`；
- `当前最佳 · 已达到时间/状态上限`；
- `尚未找到可行方案 · 搜索未完成`；
- `针对该矿区最优 · 已证明`；
- `该矿区无可行方案 · 已证明`。

完成预览必须显示证明范围为“当前矿区快照与支持模型”。对于 `CURRENT_BEST`，显示已探索、已剪枝、未决状态数；若上下界可读，显示目标差距。不得使用“局部最优”“最优方案”或绿色状态暗示未证明结果已经最优。

进度事件区分 `HEURISTIC_WARM_START` 与 `CERTIFYING`，使用户能看到程序是在寻找更好方案还是消除剩余可能性。

## 时间、取消与确定性

- 沿用现有两秒协作预算和 `maxIterations`，不新增设置。
- 捕获、已开始的单次验证和最终提交检查仍可超过两秒；搜索循环本身共享一个绝对截止时间。
- 每个昂贵边界前检查截止时间和线程中断，包括流松弛、支持分支和动态模拟之前。
- 相同快照、能力、配置和预算下，状态顺序、incumbent、证书计数和构建记录必须确定。
- 世界变化、关闭面板或选择其他矿区时，取消搜索并清除旧证书；旧 worker 不得恢复状态。

## 迁移边界

- `LocalMiningPlanner` 仍负责捕获、早期诊断、最终编译和提交前重验；方案选择与证书构造移入 `PatchOptimalSearch`。
- `ItemRouteSolver` 保留为热启动器；证明搜索共享 `TransportGeometry`、`FlowSolver` 和物理图构造规则，不能复制第二套端口语义。
- 抽取一个无状态 `PhysicalTransportGraphBuilder`，供启发式路由、证明搜索、精简器和最终验证共同使用。
- `PlanObjectiveOrder` 替代 `LocalMiningPlanner.comparePlans` 与证书中的固定 `ObjectiveValue.compareTo` 假设。
- 清理旧的永假证书构造、误导性“受限域最优”注释和无法参与证明的不完整路径枚举接口。

## 验证

### 独立 oracle

测试侧对最多若干瓦片、两种钻头和两种运输设施的小矿区做不共享生产实现的暴力枚举。比较完整目标值和规范方案，不只比较吞吐。

覆盖：

1. 热启动遗漏更便宜运输网络，证明搜索必须找到并证明更优解；
2. 非最短路径材料更低，不能被“只保留最短路径”剪掉；
3. 两个钻头共享干线时，独立路径容量相加会错误，固定费用流必须拒绝；
4. 桥方向、前向面和自动连接产生的合法/非法组合；
5. `LOW_COST`、`LOW_COMPLEXITY` 与吞吐配置均使用同一比较器和安全上界；
6. 立即截止时，有已验证方案则返回当前最佳，否则返回搜索未完成；两者都绝不标记最优；
7. 小域队列耗尽时返回 `PATCH_OPTIMAL`，上下界相等且没有搜索上限诊断；
8. 完整无解域返回 `PROVEN_INFEASIBLE`；
9. 世界修订或设置变化使证书失效；
10. 相同输入重复运行结果与证书确定。

### 集成与真实引擎

- 保留大型矿区低于十秒的管线回归；新增断言证明搜索遵守两秒协作截止时间。
- 保留所有布局、桥直连、冗余精简、循环拒绝和可达性剪枝回归。
- 在 Mindustry 30936 原生引擎中验证当前最佳与已证明小矿区方案均可建造并持续出矿。
- 实际 SDL 面板验证五种 verdict、上下界、未决状态和取消清除，不以单元测试替代可视验证。

## 验收标准

- 未穷尽证明域时，任何 API、诊断、面板或文档都不称结果为矿区最优。
- 一个小型 oracle 场景能通过生产入口返回 `PATCH_OPTIMAL`，且目标和规范方案与独立暴力枚举一致。
- 命中时间或状态上限时，有已验证方案则返回可构建的 `CURRENT_BEST`，否则返回 `SEARCH_INCOMPLETE`；两者都保留真实未决上界。
- 当前所有受支持钻头、地面运输、桥、预算和配套约束均属于证明域；任何未覆盖语义都会阻止最优标记。
- 证明搜索不使用固定半径、第一条路径、随机取样或隐藏候选上限。
- 大型矿区搜索不阻塞 UI，取消和过期 worker 行为保持正确。

## 非目标

- 不证明 `WorldSnapshot` 有限域之外的路线或未来世界状态。
- 不对未建模模组方块语义作最优承诺。
- 不引入外部 ILP、SMT、CP-SAT 或平台特定原生求解器。
- 不保证大型矿区在两秒内获得证明；它们应准时返回当前最佳。
- 不把真实游戏中的下游拥堵、电力波动或之后发生的建筑变化包含在静态证书中。
